# Fase 6.13 — borrado lógico desde modo remoto controlado

## Cambios
- Solo el **modo remoto controlado** sincroniza eliminaciones, dentro del mismo lote transaccional de hasta 100 operaciones.
- Un borrado requiere un registro presente en la última referencia remota confirmada y una revisión sin cambios.
- Si un registro ha cambiado, el lote se detiene. Se mantiene el rollback del estado local al último estado reconocido.
- El modo servidor experimental antiguo **no** sincroniza borrados. La base del navegador sigue empleando `localStorage`.

## Pruebas
`npm test` y `cd backend && npm test` para pruebas de lógica. Para integración real con Docker, seguir `backend/README.md` y `backend/run-e2e.ps1`.

## Limitaciones
Sin PostgreSQL real ni validación de borrados simultáneos, no se certifica integridad, recuperación, ni aptitud comercial. Una eliminación puede crear una entrada de actividad y superar el límite de 100 operaciones. No usar datos reales.
