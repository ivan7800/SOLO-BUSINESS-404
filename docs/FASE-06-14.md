# Fase 6.14 — Verificacion integral: alcance real

La entrega prioriza **seguridad de restauracion** y preparacion de pruebas reproducibles. No afirma que PostgreSQL haya sido probado en este entorno.

## Cambios comprobables
- `backend/restore.sh`: requiere checksum SHA256, un destino identificado como base de test y ausencia de objetos de usuario antes de invocar `pg_restore`.
- `pg_restore --single-transaction --exit-on-error`: intenta evitar restauraciones parcialmente confirmadas, siempre dentro de las limitaciones de PostgreSQL.
- Dos suites de comprobacion de precondiciones (estatica y ejecucion sin base); una prueba real de restauracion **no** se ha realizado.

## Validacion operativa pendiente
1. En maquina aislada, instalar Docker Desktop y Node.js, y ejecutar `cd backend && ./run-e2e.sh` (PowerShell: `./run-e2e.ps1`).
2. Comprobar migraciones, aislamiento por negocio, revisiones, rollback, borrado lógico y persistencia tras reinicio de API.
3. Ejecutar `backup.sh` con una base de test, crear otra base de test completamente vacia, e invocar `restore.sh` apuntando al destino vacio. Contrastar conteos y registros con consultas SQL; probar login, permisos y borrado lógico.
4. Probar los formularios en Chromium/Edge con backend activo y reinicio del servidor, y forzar fallos de red; documentar acciones y resultados.
5. Antes de produccion, diseñar gestion de secretos, monitorizacion, rotacion de sesiones, permisos, RGPD y seguridad de copias.
