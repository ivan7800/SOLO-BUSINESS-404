# Fase 6.12 — Modo remoto controlado (beta)

## Alcance

En **Conexión segura (beta)**, iniciar sesión y seleccionar **Cargar servidor y usar modo remoto (beta)**. Tras confirmación, los datos se descargan de `/api/records-all`. Una modificación normal de interfaz inicia inmediatamente una comparación de revisiones y una escritura transaccional en `/api/records-batch`, bloqueando interacciones durante el proceso. Si la confirmación falla, la UI se restaura a la última versión remota confirmada y se detiene el modo remoto. Sin reintentos silenciosos.

## Limitaciones críticas

- `localStorage` sigue existiendo como caché; todavía **no es un frontend exclusivamente remoto**.
- No se sincronizan borrados. Los borrados desde UI se rechazan y se revierte el estado local.
- Los metadatos de negocio y apariencia se conservan localmente; requieren un diseño de API dedicado.
- No hay garantía ante cierres de pestaña durante un commit no confirmado; verificar manualmente el servidor antes de continuar.
- El modo es optativo, beta y para datos ficticios. No apto para datos fiscales reales.
- La autenticación usa la API de desarrollo en HTTP loopback.

## Validación pendiente

Ejecutar `backend/run-e2e.ps1` en Windows con Docker Desktop para pruebas reales con PostgreSQL, comprobar restauración `pg_restore`, sesiones concurrentes y botones con navegador. No se considera finalizado el backend.
