# Fase 6.10 — Integración verificable

## Estado de la entrega
- La lógica local continúa en `localStorage`: **no** es persistencia definitiva en servidor.
- Se añadió prueba E2E contra PostgreSQL REAL (`backend/test/e2e-postgres.mjs`) para ejecutar sobre una base **temporal y desechable**.
- La prueba verifica: alta de dos negocios, aislamiento de lectura, bloqueo de escritura cruzada, revisiones optimistas, rollback de lotes, borrado lógico, rechazo de resurrección y persistencia tras reiniciar API.
- Cambio de endurecimiento: límite de recepción JSON calculado por bytes UTF-8 (no por número de caracteres).
- **No se ha ejecutado PostgreSQL real aquí**: no había `postgres`, `psql`, `pg_dump` ni servicio de base de datos.

## Ejecutar prueba E2E
1. Crear PostgreSQL en máquina aislada y base de datos EXCLUSIVA de pruebas. No usar datos de producción.
2. Aplicar secuencialmente `schema.sql`, `migration_v064.sql`, `migration_v065.sql`, `migration_v067.sql`.
3. En `backend` ejecutar `npm install`.
4. Definir `DATABASE_URL` para esa base de pruebas, `CONFIRM_ISOLATED_TEST_DB=YES` y ejecutar `npm run test:e2e`.
5. Una salida `PASS` debe mostrar 11 comprobaciones. Cualquier error supone que **no** se valida el backend.

## Restauración
Ejecutar `backup.sh` con pg_dump, restaurar con `restore.sh` en una SEGUNDA base vacía, verificar SHA-256 y comparar recuentos y contenido por negocio. **No ejecutado en este entorno**. Los scripts no prueban por sí solos la restauración.
